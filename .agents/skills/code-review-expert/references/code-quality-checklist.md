# コード品質チェックリスト

## エラー処理

### 指摘すべきアンチパターン

- **例外の握りつぶし**: 空の catch ブロック、またはログ出力のみの catch
  ```javascript
  try { ... } catch (e) { }  // Silent failure
  try { ... } catch (e) { console.log(e) }  // Log and forget
  ```
- **過度に広範な catch**: 具体的な型ではなく `Exception`/`Error` 基底クラスを捕捉している
- **エラー情報の漏洩**: スタックトレースや内部の詳細がユーザーに露出している
- **エラー処理の欠落**: 失敗しうる操作（I/O、ネットワーク、パース）の周囲に try-catch がない
- **非同期のエラー処理**: 未処理の promise rejection、`.catch()` の欠落、error boundary の不在

### 確認すべきベストプラクティス

- [ ] エラーが適切な境界で捕捉されている
- [ ] エラーメッセージがユーザーに分かりやすい（内部の詳細を露出していない）
- [ ] デバッグに十分なコンテキスト付きでエラーがログ出力されている
- [ ] 非同期のエラーが適切に伝播または処理されている
- [ ] 回復可能なエラーに対してフォールバックの挙動が定義されている
- [ ] 重大なエラーがアラート/監視を発火させる

### 問いかけるべき質問
- 「この操作が失敗したとき何が起きるか？」
- 「呼び出し側は何か問題が起きたと分かるか？」
- 「このエラーをデバッグするのに十分なコンテキストがあるか？」

## 性能とキャッシュ

### CPU 負荷の高い操作

- **ホットパスでの高コストな操作**: ループ内での正規表現コンパイル、JSON パース、暗号処理
- **メインスレッドのブロッキング**: 同期 I/O、worker/async を使わない重い計算
- **不要な再計算**: 同じ計算が複数回実行されている
- **メモ化の欠落**: 同じ入力で繰り返し呼び出される純粋関数

### データベースと I/O

- **N+1 クエリ**: バッチではなく要素ごとにクエリを発行するループ
  ```javascript
  // Bad: N+1
  for (const id of ids) {
    const user = await db.query(`SELECT * FROM users WHERE id = ?`, id)
  }
  // Good: Batch
  const users = await db.query(`SELECT * FROM users WHERE id IN (?)`, ids)
  ```
- **インデックスの欠落**: 未インデックスのカラムに対するクエリ
- **過剰な取得**: 数カラムしか必要ないのに SELECT * している
- **ページネーションの不在**: データセット全体をメモリに読み込んでいる

### キャッシュの問題

- **高コストな操作に対するキャッシュの欠落**: 繰り返しの API 呼び出し、DB クエリ、計算
- **TTL のないキャッシュ**: 陳腐化したデータが無期限に提供される
- **無効化戦略のないキャッシュ**: データが更新されてもキャッシュがクリアされない
- **キャッシュキーの衝突**: キーの一意性が不十分
- **ユーザー固有データのグローバルなキャッシュ**: セキュリティ/プライバシーの問題

### メモリ

- **境界のないコレクション**: 上限なく増大する配列/マップ
- **大きなオブジェクトの保持**: GC を妨げる参照の保持
- **ループ内での文字列連結**: 代わりに StringBuilder/join を使う
- **大きなファイルの一括読み込み**: 代わりにストリーミングを使う

### 問いかけるべき質問
- 「この操作の時間計算量はどれくらいか？」
- 「データが 10 倍/100 倍になったときどう振る舞うか？」
- 「この結果はキャッシュ可能か？するべきか？」
- 「1 件ずつではなくバッチ化できないか？」

## 境界条件

### Null/Undefined の扱い

- **null チェックの欠落**: null になりうるオブジェクトのプロパティにアクセスしている
- **真偽値（truthy/falsy）の混同**: `0` や `""` が有効値なのに `if (value)` を使っている
- **オプショナルチェーンの多用**: `a?.b?.c?.d` が構造上の問題を隠している
- **null と undefined の不整合**: 明確な規約なく混在して使われている

### 空のコレクション

- **空の配列が未処理**: 配列に要素があると前提しているコード
- **空オブジェクトのエッジケース**: 空オブジェクトに対する `for...in` や `Object.keys`
- **先頭/末尾要素へのアクセス**: 長さチェックなしの `arr[0]` や `arr[arr.length-1]`

### 数値の境界

- **ゼロ除算**: 除算前のチェック欠落
- **整数オーバーフロー**: 安全な整数範囲を超える大きな数値
- **浮動小数点の比較**: イプシロン比較ではなく `===` を使っている
- **負の値**: 負であってはならないインデックスやカウント
- **オフバイワンエラー**: ループの境界、配列スライス、ページネーション

### 文字列の境界

- **空文字列**: エッジケースとして処理されていない
- **空白のみの文字列**: 真偽チェックは通るが実質的に空
- **非常に長い文字列**: 長さ制限がなくメモリ/表示の問題を引き起こす
- **Unicode のエッジケース**: 絵文字、RTL テキスト、結合文字

### 指摘すべき一般的なパターン

```javascript
// Dangerous: no null check
const name = user.profile.name

// Dangerous: array access without check
const first = items[0]

// Dangerous: division without check
const avg = total / count

// Dangerous: truthy check excludes valid values
if (value) { ... }  // fails for 0, "", false
```

### 問いかけるべき質問
- 「これが null/undefined だったら？」
- 「このコレクションが空だったら？」
- 「この数値の有効な範囲は？」
- 「境界（0、-1、MAX_INT）で何が起きるか？」

## レビューで追加した訂正（PR #156）

計画時点では、空白 13 か月を「リプレイが打ち切られて測れなかった期間」と読み、設定
（損失停止・時間切れ決済）を直せば取り戻せる前提で書いていた。レビューで 2 点の誤りが出た。

1. `trades.csv` は決済のたびに 1 行が書かれる記録で、月は `exit_at` の月。使った commit の
   `src/trading/backtest/engine.py` は保存 tick を最後まで回し、保有中も equity と drawdown を
   更新している。空白月が示すのは「その月に閉じた round trip が無かった」ことだけで、未測定ではない
2. 使った tick には 2026-01-23〜2026-04-08 の 74 日欠損がある
   （`tasks/h5-macro-confirmation-ablation.md` に記録済み）

したがってノートでは次のように書く。

- 空白を「打ち切り」「未測定」と書かない。射程の問題は測れた期間の長さではなく、
  239 / 442 件の決済が 12 か月に固まっているという標本の偏りとして書く
- 上記 5 の「初めて 25 か月の比較になる」は誤り。損失停止を外して時間切れ決済を足すのは
  戦略とリスク条件を変えた別の測定であって、欠落期間の復元ではない。H5 の判定を上書きする
  材料には使わない。2 つを同時に変えると枠の解放と棄却の消滅を識別できないので、
  切り分けには片方ずつの run か risk_rejections の内訳が要る、と併記する
- 期末建玉の指標（unrealized_pnl / open_positions_at_end）は summary.json の metrics 配下。
  manifest.json は再現用の入力（commit・config・dataset・seed）で、metrics は入っていない
- 2026-02〜2026-03 は入力の tick が無いので、期間として埋めるにはバックフィルが要る
- 3% 停止に当たったとは断定しない。判定は絶対額ではなく高値に対する割合で、signal が出て
  RiskEngine が評価されたときにだけ棄却が記録される。最大ドローダウンの額は証拠にならないので、
  棄却コード HWM_DRAWDOWN_WITHIN_LIMIT を確認するまでは仮説として書く
- 月別件数は `exit_at` の月なので、確認レッグが効いた時期の根拠にはしない。決済が集中した月として
  限定して書き、作用範囲を言うには `entry_at`（可能なら setup 時刻）での再集計が要ると明記する。
  run 成果物は VPS 側にあり本 PR では再集計できないため、「次のステップ」に回す
- 月別件数が一致した 8 か月について「両腕がほぼ同じ経路をたどっている」とは書かない。
  レッグが落とした setup の代わりに別の setup が約定すれば月合計は一致するため、
  `entry_id` と setup 時刻の照合なしには言えない
- 「次のステップ」の micro_live overlay の項目は、SHADOW 降格が反映済みの現状に合わせて書き直す

## 実測で確定した事実（本節が上の記述に優先する）

VPS の run 成果物から `trades.csv` と `summary.json` の `risk_rejections` を月別に数え直し、
次が確定した。上の「判明した事実」「レビューで追加した訂正」と食い違う箇所は、本節を採る。

- 上の月別件数の表は `exit_at` ではなく **`entry_at`（建てた時刻）** の集計だった。数値は正しい。
  決済の月で数え直しても分布の形は変わらず、動くのは月境界をまたいだ建玉が各境界で 1 件ずつ
- 空白 11 か月（2025-02〜2025-12）の原因は銘柄あたりの建玉上限。両腕とも毎月
  `MAX_OPEN_POSITIONS_PER_SYMBOL` の棄却が記録されている（確認ありは 26〜169 件、
  確認なしは 95〜578 件）。signal は毎月出ていて、`RiskEngine` まで届いたうえで落ちていた
- **口座水準の 3% 停止（`HWM_DRAWDOWN_WITHIN_LIMIT`）は空白期間には掛かっていない。**
  確認ありは全期間で 0 件、確認なしは run の最終月 2026-08 の 99 件だけ。最大ドローダウンが
  3% を超えていても停止の証拠にならない。ただし確認なしの最終月には棄却があるので、
  旧閾値が H5 の標本に一切影響していないとまでは言えない
- 2026-02〜2026-03 に棄却の記録が無いのは、tick の 74 日欠損（2026-01-23〜2026-04-08）で
  評価自体が走らないため
- `entry_at` の集計で分かるのは件数差の出た月まで。確認レッグが setup を落とした月を特定するには、
  両腕の setup 時刻とゲートの判定結果の照合が要る（本 PR では行っていない）
- 空白を埋めるのは時間切れ決済であって、研究リプレイから口座水準の損失停止を外す変更
  （ADR-037 で採用済み）ではない。H5 では空白期間にその停止が掛かっていなかったため

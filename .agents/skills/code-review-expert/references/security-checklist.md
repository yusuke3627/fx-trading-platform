# セキュリティと信頼性のチェックリスト

## 入出力の安全性

- **XSS**: 安全でない HTML 注入、`dangerouslySetInnerHTML`、エスケープされていないテンプレート、innerHTML への代入
- **Injection**: 文字列連結やテンプレートリテラルによる SQL/NoSQL/コマンド/GraphQL インジェクション
- **SSRF**: 許可リスト検証なしにユーザー制御の URL が内部サービスへ到達する
- **Path traversal**: サニタイズなしにユーザー入力がファイルパスに使われる（`../` 攻撃）
- **Prototype pollution**: JavaScript における安全でないオブジェクトのマージ（ユーザー入力を伴う `Object.assign` やスプレッド）

## AuthN/AuthZ

- 読み書き操作におけるテナントチェックや所有権チェックの欠如
- 認証ガードや RBAC の強制がない新規エンドポイント
- クライアントから渡されるロール/フラグ/ID を信頼している
- アクセス制御の破綻（IDOR - Insecure Direct Object Reference）
- セッション固定攻撃や脆弱なセッション管理

## JWT とトークンのセキュリティ

- アルゴリズム混同攻撃（`RS256` を期待しているのに `none` や `HS256` を受け入れる）
- 脆弱な、またはハードコードされたシークレット
- 有効期限（`exp`）の欠如、または検証していない
- JWT ペイロード内の機密データ（トークンは base64 であり暗号化されていない）
- `iss`（発行者）や `aud`（対象者）を検証していない

## シークレットと PII

- コード/設定/ログ内の API キー、トークン、認証情報
- git 履歴内のシークレット、またはクライアントに公開された環境変数
- PII や機密ペイロードの過剰なロギング
- エラーメッセージにおけるデータマスキングの欠如

## サプライチェーンと依存関係

- 悪意ある更新を許してしまう、固定されていない依存関係
- 依存関係の混同（プライベートパッケージ名の衝突）
- 完全性チェックなしに信頼できないソースや CDN からインポートする
- 既知の CVE を持つ古い依存関係

## CORS とヘッダー

- 過度に寛容な CORS（認証情報付きの `Access-Control-Allow-Origin: *`）
- セキュリティヘッダーの欠如（CSP、X-Frame-Options、X-Content-Type-Options）
- 内部ヘッダーやスタックトレースの露出

## 実行時のリスク

- 上限のないループ、再帰呼び出し、巨大なメモリ内バッファ
- 外部呼び出しにおけるタイムアウト、リトライ、レート制限の欠如
- リクエストパス上でのブロッキング操作（非同期コンテキストでの同期 I/O）
- リソース枯渇（ファイルハンドル、コネクション、メモリ）
- ReDoS（Regular Expression Denial of Service）

## 暗号

- 脆弱なアルゴリズム（セキュリティ目的での MD5、SHA1）
- ハードコードされた IV やソルト
- 認証なしの暗号化（ECB モード、HMAC なし）
- 不十分な鍵長

## 競合状態

競合状態は、断続的な障害やセキュリティ脆弱性を引き起こす見つけにくいバグである。特に次の点に注意すること:

### 共有状態へのアクセス
- 複数のスレッド/ゴルーチン/非同期タスクが同期なしに共有変数へアクセスする
- グローバル状態やシングルトンが並行して変更される
- 適切なロックなしの遅延初期化（double-checked locking の問題）
- スレッドセーフでないコレクションを並行コンテキストで使用する

### Check-Then-Act（TOCTOU）
- アトミック操作を伴わない `if (exists) then use` パターン
- 認可が変化しうる `if (authorized) then perform`
- ファイル存在チェックに続くファイル操作
- 残高チェックに続く減算（金融操作）
- 在庫チェックに続く発注

### データベースの並行性
- 楽観的ロックの欠如（`version` カラム、`updated_at` チェック）
- 悲観的ロックの欠如（`SELECT FOR UPDATE`）
- トランザクション分離なしの read-modify-write
- アトミック操作を伴わないカウンターのインクリメント（`UPDATE SET count = count + 1`）
- 並行 insert における一意制約違反

### 分散システム
- 共有リソースに対する分散ロックの欠如
- リーダー選出の競合状態
- キャッシュ無効化の競合（書き込み後の陳腐化した読み取り）
- 適切な順序付けなしのイベント順序依存
- クラスタ操作におけるスプリットブレインのシナリオ

### 注意すべき一般的なパターン
```
# Dangerous patterns:
if not exists(key):       # TOCTOU
    create(key)

value = get(key)          # Read-modify-write
value += 1
set(key, value)

if user.balance >= amount:  # Check-then-act
    user.balance -= amount
```

### 確認すべき問い
- 「2 つのリクエストがこのコードに同時に到達したら何が起こるか?」
- 「この操作はアトミックか、それとも中断されうるか?」
- 「このコードはどの共有状態にアクセスするか?」
- 「高並行性のもとでこれはどう振る舞うか?」

## データ整合性

- トランザクションの欠如、部分書き込み、一貫性のない状態更新
- 永続化前の脆弱な検証（型強制の問題）
- リトライ可能な操作における冪等性の欠如
- 並行変更による更新の喪失

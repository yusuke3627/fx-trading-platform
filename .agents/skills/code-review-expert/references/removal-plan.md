# 削除・反復計画テンプレート

## 優先度レベル

- [ ] **P0**: 即時の削除が必要（セキュリティリスク、重大なコスト、他作業のブロック）
- [ ] **P1**: 現スプリント内で削除
- [ ] **P2**: バックログ／次回の反復

---

## 今すぐ安全に削除できるもの

### 項目: [名称／説明]

| 項目 | 詳細 |
|-------|---------|
| **場所** | `path/to/file.ts:line` |
| **根拠** | なぜ削除すべきか |
| **証拠** | 未使用（参照なし）、死んだフィーチャーフラグ、非推奨 API |
| **影響** | なし／低 - 稼働中の利用者なし |
| **削除手順** | 1. コードを削除 2. テストを削除 3. 設定を削除 |
| **検証** | テストを実行し、実行時エラーがないか確認し、ログを監視する |

---

## 削除を見送る（計画が必要）

### 項目: [名称／説明]

| 項目 | 詳細 |
|-------|---------|
| **場所** | `path/to/file.ts:line` |
| **見送る理由** | 稼働中の利用者あり、移行が必要、ステークホルダーの承認が必要 |
| **前提条件** | フィーチャーフラグを 2 週間オフにする、テレメトリで使用量 0 を確認 |
| **破壊的変更** | API／契約の変更を列挙する |
| **移行計画** | 利用者が移行するための手順 |
| **タイムライン** | 目標期日またはスプリント |
| **オーナー** | 責任を持つ担当者／チーム |
| **検証** | 安全な削除を確認するための指標（エラー率、使用回数） |
| **ロールバック計画** | 問題が見つかった場合の復旧方法 |

---

## 削除前のチェックリスト

- [ ] コードベース全体で全参照を検索した（`rg`）
- [ ] 動的／リフレクションベースの使用を確認した
- [ ] 外部の利用者がいないことを確認した（API、SDK、ドキュメント）
- [ ] フィーチャーフラグのテレメトリを確認した（該当する場合）
- [ ] テストを更新／削除した
- [ ] ドキュメントを更新した
- [ ] チームに通知した（共有コードの場合）

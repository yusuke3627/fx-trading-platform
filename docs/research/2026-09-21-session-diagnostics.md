# 固定した時間帯の寄与を探索する

Issue #204。保存済みBid/Askを使い、東京・ロンドン・NYの開始後1時間と直前1時間を
同じ営業日・同じ方向で比較する。戦略登録や発注は行わない。

今回は合成データによるCLI動作確認までで、実データの収益性は未測定。
H6の棄却や、別の政策文書研究の判定は変更しない。

## 実行方法

```bash
.venv/bin/python -m trading.backtest.session_study \
  --plan tests/fixtures/session_study/plan.json \
  --quotes tests/fixtures/session_study/quotes.jsonl \
  --output-dir /tmp/session-study-example
```

出力先は新規ディレクトリにする。入力計画のコピー、`report.json`、`report.md`を作る。
終了コード0はレポート生成成功、2は入力・出力エラーであり、0は採用判定を意味しない。
入力ファイルのhash、コードのGit状態、全計測日・除外理由・採用quoteを残す。
`simulated`の入力には「合成データのみ」と表示し、確認候補を出さない。

## 結果を見る前に固定するもの

計画JSONの正本は `session_study.Plan`。fixtureの値は動作確認用であり、実測の計画として
そのまま使わない。対象InstrumentSpec・期間・価格の保存元と抽出条件を記入し、最小限
検出したい純pips、必要営業日数、その標本数の根拠、block長を先に固定する。
CLIは検出力を推計せず、入力した標本数の十分性を保証しない。標本数の根拠は、対象期間を
見てから調整せず、独立した期間の変動幅等から決める。

- 窓は既存 `SESSION_WINDOWS_LOCAL` と同じIANA定義。東京09時、ロンドン08時、NY08時の
  各ローカル時刻を使い、DSTは市場ごとに変換する。窓幅は前後1時間に固定。
- 各市場のローカル日付が月曜から金曜の日を対象にする。月曜も含め、`week_open`として
  記録する。他市場の開場中かは`active_sessions`に残し、重複市場を別注文に数えない。
- 指標発表・休場日は入力カレンダーの半開区間`[start, end)`で明示する。価格だけから
  平穏な日・休場日を推測しない。前後の保有窓と重なる場合は、対全体を予定除外する。
  カレンダーの確認範囲外は保留とする。`calendar_source`に出典と対象イベント群を残す。
  CLIは記入された範囲内のカレンダーが網羅的かを外部照合しない。
- brokerのNY先行時間を入力し、前後窓のいずれかでrolloverに触れる対は事前除外する。
  swapを0とみなさない。本ツールはrolloverを跨ぐ仮説を評価しない。
- 遅延は3境界すべてに同じ固定ミリ秒を加える。約定価格は、その時点までに観測した
  最新Bid/Askを、最大経過秒以内の場合だけ使用する。未来quoteを遡って使わない。
  受信済み提示で約定可能と仮定する感度分析であり、実約定、板、拒否、部分約定を再現しない。
- LONGは退出bid−開始ask、SHORTは開始bid−退出askをpip sizeで割り、片道slippageを2回と
  往復手数料`commission_pips_round_trip`を引く。手数料は対象条件でpips換算して入力する。
  手数料なしも明示的な0が必要。spreadは保存Bid/Ask由来。mid方向変化も別に保存する。

## 価格ファイルと時刻

quote JSONLは #203 と同じ `QuoteObservation` 形式を使う。価格はDecimal文字列、各行は
symbol・bid・ask・`observed_at: {at, basis}`。時刻昇順・重複なしで、対象symbolとbasisを
揃える。全入力をストリームで検証してhash化し、必要な境界のquoteだけを保持する。

`observed_utc`は実際の受信時刻、`reconstructed`は変換根拠のある復元時刻、`simulated`は
合成時刻。brokerの壁時計にUTCのラベルを付けただけの値を渡さない。既存の研究用復元は
`research.reconstructed_tick` / ADR-014を参照し、実受信履歴とは区別する。現在のAPIから
過去を取得しても、その時点で実際に利用可能だった受信履歴の証明にはならない。

`quotes_complete`は保存元を確認した利用者の宣言であり、ツールによる証明ではない。
宣言false・カレンダー不足・価格欠測・鮮度超過・data_outageが1日でもあれば、その市場の
判定を保留する。入力末尾以後へ価格を延長しない。予定された指標発表・休場・rolloverの
除外と、データが足りない除外を分ける。価格の計測可能率は窓の3境界についてのもので、
途中の価格経路・ストップ約定の検証ではない。

## 比較と次の判断

全3市場×2方向について、開始後・直前・その差の計18区間を必ず出す。営業日の並びを
維持する循環moving-block bootstrapを使い、予定除外日も欠測位置として残す。
各系列に同じseedを使う。18区間には全体90%を目安とするBonferroni補正を加える。
区間はbootstrapによる近似であり、少ない日数やblock長の妥当性を補正だけで解決しない。
原系列・試した計画を保存し、別期間・別コスト等の再試行は追加探索として記録する。
この18比較の補正は、利用者が繰り返した別runまで含めない。

- 必要営業日数に未達、または計測に必要な情報が不足: 保留。
- 開始後の純pips、または直前に対する差の区間上限が0以下: この仮説を中止。
- 開始後の下限が事前の最小効果以上、かつ差の下限が0より大きい: 未使用期間での確認候補。
- その他: 判定不能。標本や計画を変更する場合は、同じ評価期間で窓を探し直さない。

出力は常に`split=exploratory`・`profitability_established=false`。既に見た2024-08〜2026-08
を確認用と呼び替えない。候補を1つに固定して別途登録し、過去の全研究で未使用と確認できる
期間か、登録後に蓄積する期間で確認する。本CLIはその未使用性を証明せず、確認用評価の
自動実行も行わない。実測入力、標本数の根拠、確認用の未使用期間が次の研究に必要である。
